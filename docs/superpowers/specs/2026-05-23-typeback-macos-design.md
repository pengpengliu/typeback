# Typeback macOS 设计

## 目标

构建一个小型原生 macOS 菜单栏应用，在全局键盘闲置一段时间后，自动把当前输入法切换回指定输入源。

默认行为：

- 应用作为菜单栏工具在后台常驻。
- 全局键盘 10 秒无输入后，自动把当前输入源切换到 ABC。
- 闲置时间和目标输入源可以由用户自定义。
- 用户可以在不退出应用的情况下启用或停用自动切换。
- 用户可以配置开机自动启动。

## 范围

包含：

- 使用 Swift、SwiftUI，并在需要处桥接 AppKit 的原生 macOS 应用。
- 菜单栏状态项。
- 设置窗口。
- 全局键盘闲置监听。
- 输入源枚举与切换。
- 偏好设置持久化。
- 开机自动启动。
- Accessibility 权限检测与引导。

不包含：

- 按应用配置输入法规则。
- 基于鼠标、触控板、滚动或窗口焦点的闲置检测。
- 云同步。
- 复杂自动化规则。
- 输入法安装或修改。

## 推荐方案

使用原生 SwiftUI macOS 应用，并在系统能力接入处桥接 AppKit。

这个方案体积小，能直接使用 macOS 菜单栏、全局键盘事件监听、输入源切换、权限检测和登录项管理 API。Electron 或 Tauri 对这个需求过重，而且核心能力仍然需要 native bridge，不推荐作为第一版方案。

## 架构

### 应用入口

`TypebackApp` 负责应用启动，并组装长期存活的服务：

- `PreferencesStore`
- `InputSourceManager`
- `KeyboardIdleMonitor`
- `PermissionManager`
- `LaunchAtLoginManager`
- `StatusBarController`

应用应隐藏 Dock 图标，以后台 accessory app 的方式运行。

### 菜单栏

`StatusBarController` 负责菜单栏图标和菜单动作。

菜单项：

- 启用开关。
- 当前 reset 目标，例如 `Reset to: ABC`。
- 当前闲置时间，例如 `Idle: 10s`。
- `Settings...`
- `Quit`

菜单需要反映权限和配置状态。如果缺少 Accessibility 权限，启用状态必须明确显示为不可用，而不是静默失败。

### 设置窗口

设置界面只暴露必要控制项：

- 启用开关。
- 闲置时间输入，限制在 `1...3600` 秒。
- 目标输入源下拉选择，数据来自系统当前可用输入源。
- 开机自动启动开关。
- Accessibility 权限状态。
- 打开系统设置授权页的按钮。

设置变更即时生效：

- 修改闲置时间后，重新安排 idle timer。
- 修改目标输入源后，下一次 idle reset 使用新目标。
- 关闭启用开关后，停止事件监听并清理 timer。
- 打开启用开关后，如果权限可用，则开始监听。

### 键盘闲置监听

`KeyboardIdleMonitor` 监听全局 `keyDown` 事件。

每次键盘事件到来时：

1. 记录最新键盘活动时间。
2. 取消旧 idle timer。
3. 按当前配置的闲置时间重新安排 timer。

timer 触发时：

1. 确认应用仍处于启用状态。
2. 确认配置的目标输入源仍然存在。
3. 读取当前输入源。
4. 如果当前输入源和目标输入源不同，则切换到目标输入源。

只有键盘无输入计为闲置。鼠标移动、点击、滚动和应用焦点变化都不重置 timer。

### 输入源管理

`InputSourceManager` 封装 Text Input Source Services API：

- 枚举可选择的输入源。
- 读取当前选中的输入源。
- 按稳定的 source ID 切换到目标输入源。
- 返回用于 UI 展示的输入源名称。

默认目标输入源为 `com.apple.keylayout.ABC`。

如果配置的目标输入源不存在，应用不应尝试切换。菜单和设置窗口需要显示目标无效，并要求用户重新选择有效输入源。

### 偏好设置

`PreferencesStore` 持久化：

- `enabled: Bool`，默认 `true`。
- `idleSeconds: Int`，默认 `10`。
- `targetInputSourceID: String`，默认 `com.apple.keylayout.ABC`。
- `launchAtLogin: Bool`，默认 `false`。

使用 `UserDefaults` 足够，不需要引入更重的存储层。

### 开机自动启动

`LaunchAtLoginManager` 优先使用部署目标支持的现代 ServiceManagement 登录项 API。设置页开关应尽量反映系统中的真实登录项状态。

### 权限

应用需要监听全局键盘事件，因此需要 Accessibility 权限。

权限行为：

- 启动时检测 Accessibility 权限。
- 权限缺失时，不启动全局键盘监听。
- 在菜单和设置窗口中显示权限缺失状态。
- 提供打开对应系统设置页的动作。
- 当应用变为 active 或设置窗口出现时，重新检测权限。
- 授权完成后，不要求重启应用，应能自动开始监听。

除非实际测试证明必要，否则不申请更宽的权限。

## 运行时行为

启动流程：

1. 读取偏好设置。
2. 创建菜单栏菜单。
3. 检测权限。
4. 如果应用启用且权限可用，开始键盘闲置监听。

键盘输入：

1. 全局 `keyDown` 事件到来。
2. 重置 idle timer。

闲置超时：

1. timer 在配置的闲置时间后触发。
2. 应用检查切换是否有效且必要。
3. 应用切换到配置的目标输入源。

设置更新：

1. 持久化新值。
2. 通知相关服务。
3. 服务更新 timer、监听状态、菜单文案和登录项状态。

## 错误处理

预期失败状态：

- 缺少 Accessibility 权限。
- 目标输入源不存在。
- 输入源切换失败。
- 登录项状态更新失败。

处理策略：

- 应用继续运行。
- 避免反复弹出打扰用户的提示。
- 在设置页和菜单中显示稳定状态。
- 在开发构建中记录诊断信息。
- 权限缺失时，不应静默展示为已正常启用。

## 测试与验证

构建验证：

- Xcode 项目创建后使用 `xcodebuild` 验证构建。

手动验证：

- 应用能作为菜单栏工具启动。
- Dock 不显示应用图标。
- Accessibility 权限缺失状态显示清晰。
- 授权后无需重启即可开始键盘监听。
- 全局键盘输入会重置 idle timer。
- 达到配置的闲置时间后，当前输入源切换到 ABC。
- 如果当前输入源已经是 ABC，不做多余切换。
- 修改闲置时间后立即生效。
- 修改目标输入源后，下一次 idle reset 使用新目标。
- 停用应用后停止监听。
- 开机自动启动开关能更新系统登录项。

## 风险

- macOS 权限行为可能因系统版本不同而变化，需要在目标 macOS 版本上手动验证。
- 输入源 ID 实践中通常稳定，但用户可能删除或禁用输入源，应用必须处理目标输入源缺失。
- 全局事件监听在沙盒环境下可能存在差异。第一版应保持 entitlements 最小化，并在启用沙盒限制前验证行为。

## 实现默认值

- 最低支持 macOS 版本：macOS 13.0。
- 初始分发目标：本地开发构建，使用标准 Xcode 签名。Developer ID 签名不纳入第一版实现范围。
- 菜单栏符号：先使用能表达键盘或输入切换含义的 SF Symbol，等核心行为稳定后再考虑完整视觉设计。
